Review of CNRFC and UCRB raster publication pilots
Review date: 2026-11-12

Publication reviewed:
  Local: /cw3e/mead/projects/cwp206/agentization/hydro_ops/web/publications/test-20251001-20261111-v2/
  Web: https://cw3e.ucsd.edu/hydro/nrt_hydro/nwm/
  Revision: test-20251001-20261111-v2

Basis: docs/data-publishing/common-contract.md and common-types.md in the
hydromet-map repository. This is a review against proposed guidance, not
certification against a finalized schema. No publication or application files
were changed during the review.

OVERALL ASSESSMENT

These are good pilot publications and follow much of our guidance. Sharing one
folder and one legends.json is appropriate. The main remaining work is making
scientific interpretation complete and correcting a transparency mismatch,
rather than reorganizing the directories.

WHAT ALREADY WORKS WELL

- Organization: Shared legends, separate family descriptions, explicit
  availability, and a preferred timeline are sensible divisions.
- Asset integrity: All 1,750 CNRFC and 1,744 UCRB listed PNGs exist and match their
  SHA-256 checksums. Their image dimensions and indexed-PNG bit depths match the
  metadata.
- Availability: Asset IDs and dimension combinations are unique. Timeline
  references resolve and agree with the assets. The retro-preference policy is
  followed.
- Placement: EPSG:3857, image dimensions, outer-edge coordinates, corner order,
  and row orientation are specified. Projected extents agree with geographic
  corners.
- Time: Assets explicitly define UTC intervals, start-date labeling, and
  exclusive end boundaries.
- Legends: Exact RGBA colors, discrete boundaries, boundary inclusion, units,
  and intentionally transparent bins are provided.
- Scientific caveats: The percentile reference period, SWE cutoff, and warning
  about model states not reflecting recent forcing revisions are useful.
- Serving: Sampled family manifests and PNGs return HTTP 200, appropriate MIME
  types, and CORS headers; their contents match the local copies.

PRIORITY REVISIONS

1. HIGH: Make PNG transparency agree with the legends.

Sampled temperature, precipitation, and SWE-percentile images contain #ffffff00,
while their legends declare missing as #00000000 and do not otherwise declare
transparent white. Define outside-domain/background pixels separately from
missing estimates and valid hidden bins. Make rendered pixels and declarations
agree.

For example, the first CNRFC temperature PNG contains 829,910 transparent-white
pixels, so this is not merely an unused palette entry. The image alone does not
establish whether those pixels are outside the domain or missing estimates.

2. HIGH: Add a complete variable dictionary.

Variable IDs and legend units are present, but scientific meanings remain
partly implicit. Add shared variable definitions with labels, descriptions,
quantities, units, temporal aggregation, source fields, and processing methods.
Both families can reference the same file.

3. HIGH: Define the statistic within each time interval.

An interval alone does not identify the statistic within it. Daily temperature
could mean an average or a snapshot; daily precipitation needs an explicit
accumulation definition. Declare aggregation per variable and resolution.
Explain conversion from RAINRATE to precipitation depth, temperature conversion,
and whether daily soil-water/SWE ranks describe averages or particular sampling
times.

4. HIGH: Specify missing and invalid source-value treatment.

Document source sentinels, masks, valid ranges, and treatment of negative
precipitation before coloring. Open-ended precipitation bins must not silently
hide invalid negative values as low precipitation.

5. MEDIUM: Complete identity and provenance metadata.

Family titles, contact information, attribution, processing/model versions, and
actual reuse terms are missing or incomplete. Add these fields. Replace
"Confirm public reuse terms before server deployment" with explicit terms or an
explicit restriction. Keep the test-only status.

6. MEDIUM: Make sourceIdentity portable and precisely representable.

sourceIdentity contains undocumented positional integers exceeding JavaScript's
exact integer range. Use named fields and strings for large integers. Explain
their meaning. For durable provenance, prefer source checksums or immutable
source identifiers over filesystem identities alone.

7. MEDIUM: Clarify coverage and gap semantics.

Gaps omit resolution and stream; coverage ends in November although monthly
assets end with October. Define coverage per product/variable/resolution and
clarify whether a gap means no preferred asset or a missing individual stream.
Distinguish an incomplete current month from a missing completed month.

TRANSPARENT IMAGES AND DATA QUALITY

69 CNRFC and 53 UCRB precipitation images have visiblePixels: 0. That can be
perfectly valid when all precipitation falls below the highlighting threshold.
Add counts such as:

- Pixels inside the domain.
- Pixels with valid estimates.
- Missing pixels inside the domain.
- Valid pixels intentionally hidden.
- Visible pixels.

This lets a consumer distinguish "nothing highlighted" from "no usable data."
Different fully transparent RGB colors are not a reliable distinction after
browser rendering. Counts are sufficient for whole-image status; pixel-level
interrogation would need a separate mask or numerical companion.

RECOMMENDED ORGANIZATION

Retain the existing structure and add a shared variables.json. Keep each
responsibility clear:

- variables.json: Scientific meaning, units, aggregation, quality rules, and
  statistical methods.
- legends.json: How physical values or ranks map to colors.
- family.json: Domain, placement, supported dimensions, provenance, and
  metadata links.
- availability.json: Authoritative list of actual assets.
- timeline.json: Preferred assets when multiple streams cover the same interval.
- coverage.json: Compact summaries and explained gaps.

Generate timeline and coverage from availability records where possible, so
they cannot drift apart.

ADDITIONAL IMPROVEMENTS

- Expand percentile-method documentation. Explain whether the 31-day window is
  centered, leap-day handling, minimum sample requirements, climatology-table
  version, and soil-layer depths and weighting formula. A linked methods
  document is fine.
- Separate suggested display conversions from scientific definitions. The
  supplied inch and Fahrenheit conversions are useful, but native quantity/unit
  metadata should drive the app's common conversion system. Percentile ranks
  should explicitly remain dimensionless.
- Specify display resampling separately. "Projected native cell footprints,
  flat colors, no antialiasing" describes production. Add an explicit
  nearest-neighbor display recommendation for these discrete bins.
- Document source-reference resolution. Paths such as forcing/outputs/... appear
  to identify production inputs, not downloadable assets relative to the
  manifest. Declare their root or mark them as provenance-only identifiers.
- Version the public release location. The local directory is revision-specific,
  but /nwm/ is not visibly versioned. If it will change, expose immutable revision
  URLs and make the stable entry point link to a release.
- Optimize indexes later. CNRFC availability is about 1.8 MB and its timeline
  about 0.5 MB before compression. That is reasonable for testing; year/month
  partitions and HTTP compression would help as the archive grows.

APPLICATION INTEGRATION

These files are not yet directly consumable by the existing manifest adapter.
That adapter expects the earlier Landsat-specific shape and filters images
using positive visible-pixel counts, a rule unsuitable for these precipitation
maps. Adapt the app to the agreed publication structure rather than force these
datasets into that older format.

RECOMMENDED NEXT ROUND AND REVIEW LIMITS

Keep this layout, first fix the transparency contract and add the shared
variable definitions, then run a browser integration pilot.

All listed PNGs were checked for existence, checksum, and relevant PNG header
metadata. Decoded pixel colors were sampled for each variable/resolution in
both families; live HTTP checks sampled each family's manifest and one PNG.
These checks establish structural consistency. They do not independently
verify source-to-image scientific calculations or geographic alignment against
reference features. Full browser integration was not performed.
